# Model-derived spike diagnostic

After loading connectivity, Start spike diagnostic opens a separate measured-soma rendering driven by actual `SparseLif.step()` spike indices. The upper anatomy panel and Fly gameplay remain DummyBrain. The new panel is labeled model-derived spikes with artificial stimulation; neither the activity nor inputs are presented as biological recordings.

The diagnostic runs the same 120-tick sequential mapped assay: all-positive signs, LIF_V1 parameters, threshold-sized current to left visual-projection neurons for 60 ticks and right neurons for 60 ticks. It resets at the start, with the original assay's carryover between sides intentionally preserved. The full-graph final trace hash must equal 322408360. Independent stimulus controls remain available as a separate suite.

## Ownership and display semantics
The worker owns graph and model state. Each response transfers a newly allocated full-population Uint8 activity array: 255 only for neurons spiking in that tick, zero otherwise. Scalar tick, spike count, trace hash and graph identity accompany it. The graph identity must match loaded anatomy before ingest. `visual_indices` maps full-population activity onto measured somas; unpositioned graph neurons remain simulated and included in the spike count. Renderer glow decay is presentation-only and never changes model state.

The UI requests one step only after the previous response plus a 34 ms delay. There is at most one pending request, so no unbounded activity queue; playback is at most 30 model ticks/sec and slows with computation/rendering. It is not a biological time scale or real-time neural target. Each activity payload is 166,700 bytes, approximately 5 MB/sec at 30 frames/sec; no repeated graph transfer occurs. Temporary activity arrays and rendering buffers add memory beyond graph/model state.

At tick 120 the worker releases the model and the UI labels completion; the last frame remains with its explicit tick while glow fades. Start after completion starts fresh. Reset diagnostic replaces the run with a new ID and clears the view. Clear diagnostic stops the run, clears glow and counters, and releases model ownership while retaining connectivity. Unload terminates the worker and unmounts/disposes the diagnostic renderer. Worker errors clear diagnostic state. Run IDs reject late frames after reset/clear, and timers are cancelled on release/unmount. Benchmarks and diagnostics are mutually exclusive in UI and worker.

## Verification
A small directed fixture proves activity pixels follow actual delayed spikes, remain independent across returned buffers and stop after 120 ticks. Production Chrome tests start, reset mid-run, match the full mapped trace, clear counters, unload during playback and verify gameplay continues. Existing measured mapping and Canvas fallback rendering paths are reused; a dedicated full-trace Canvas test checks rendering-independent model behavior. The second renderer is created only after starting the diagnostic, so idle network preparation does not add another rendering loop. The final UI screenshot is inspected. No directional-control or biological-accuracy claim follows from visualization.
